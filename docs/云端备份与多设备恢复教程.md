# 云端备份与多设备恢复教程

本教程对应“高级设置 → 存储”中的 GitHub、邮箱和 WebDAV 功能。云端文件均应使用独立密码加密；云端账号密码、访问令牌和自动化设置不会写入备份文件。

## GitHub 私有仓库

1. 在 GitHub 新建一个 Private 仓库，建议只用于粘人精备份。
2. 在 Settings → Developer settings → Personal access tokens → Fine-grained tokens 创建令牌。
3. Repository access 只选择刚创建的仓库；Repository permissions 只将 Contents 设为 Read and write。
4. 应用内仓库填写 `用户名/仓库名`，分支通常填写 `main`，然后点击“测试仓库权限”。
5. 设置备份密码后上传。大文件会按 8 MB 分卷；只有所有分卷和完整性清单都上传成功，备份才会出现在云端记录中。
6. 换机时配置相同仓库，进入“管理 GitHub 云端记录”，输入原备份密码。优先选择合并；确认新设备没有重要数据时才使用覆盖。

GitHub 会保留提交历史，即使从当前目录删除旧分卷，仓库历史仍可能增长。媒体很多时应将 GitHub 作为少量灾备目的地，主要备份建议使用 WebDAV。

## 邮箱备份

1. 选择完整备份或分类备份并设置独立密码。
2. 点击生成后，在系统分享面板选择邮件应用，确认 `.nrtbackup` 文件已经成为附件，再发送给自己。
3. 如果系统不支持文件分享，应用会下载文件；请手动把它添加到邮件附件。
4. 不要把解密密码写在同一封邮件里。
5. 恢复时下载附件，在“从本地恢复数据”中打开，先预览差异再恢复。

“定期生成待发送备份”只会在应用打开且已到周期时运行，浏览器不能在应用长期关闭时替用户发送邮件。

## WebDAV 网盘

1. 在网盘安全设置中开启 WebDAV，并创建应用专用密码。
2. 建议为粘人精创建独立目录，例如 `/clingy-backups/`。
3. 在应用中填写目录 URL、账号、应用密码和自动备份加密密码。
4. 点击“连接并保存”。若账号正确但仍失败，通常是服务端没有允许浏览器跨域请求。
5. 设置保留版本和自动周期。自动备份会在应用打开或重新联网且已到周期时执行。
6. 新设备填写相同 WebDAV 配置，刷新云端列表并恢复。默认使用“追加合并”。

## 使用免费云主机自建 WebDAV

下面以“带长期免费计算额度的 Ubuntu 云主机 + SFTPGo Community”为通用路线。免费政策会变化，创建实例前必须在云平台费用估算中确认金额为 0；不要仅凭教程假设永久免费。

### 1. 准备云主机

1. 注册提供长期免费计算额度的云平台，例如 Oracle Cloud Free Tier，选择标有免费额度资格的 Ubuntu 实例。
2. 创建持久系统盘并保留 SSH 私钥。
3. 安全组只开放 SSH、HTTP 和 HTTPS；WebDAV 内部端口不要直接暴露到公网。
4. 准备一个域名或免费 DDNS 主机名，解析到云主机公网 IP。

### 2. 安装 SFTPGo

在 Ubuntu 上按照 Docker 官方文档安装 Docker Engine，然后用 SFTPGo Community 镜像运行服务。至少持久化以下两类目录：

- SFTPGo 配置和数据库目录；
- 用户备份文件目录。

Web 管理端建议只通过 SSH 隧道访问。创建首个管理员后，再创建一个权限受限的普通用户专门保存备份。WebDAV 服务可使用独立内部端口，例如 `10080`。

### 3. 配置 HTTPS 和 CORS

使用 Caddy、Nginx 或云平台 HTTPS 入口，把 `https://backup.example.com/dav/` 反向代理到 SFTPGo WebDAV 内部端口。必须使用浏览器信任的有效证书。

在 SFTPGo `webdavd` binding 的 CORS 设置中：

- 开启 CORS；
- `allowed_origins` 只填写粘人精网页的完整来源，不要长期使用 `*`；
- 允许 `OPTIONS`、`PROPFIND`、`GET`、`PUT`、`DELETE`；
- 允许 `Authorization`、`Depth`、`Content-Type`；
- 暴露 `ETag`、`Last-Modified`、`Content-Length`；
- 开启 credentials，并设置合理的预检缓存时间。

完成后，在应用中填写 `https://backup.example.com/dav/`、普通用户名和密码进行连接测试。

### 4. 运维检查

- 每月至少检查一次最近备份时间，并实际下载验证一份备份。
- 定期更新 Ubuntu、Docker 和 SFTPGo。
- 云主机快照不能替代应用备份；应用备份也不能替代服务器磁盘快照。
- 不要把管理员密码、SSH 私钥或备份解密密码放在同一个网盘目录。
- 若云平台准备回收空闲免费实例，应及时把备份迁移到另一目的地。

## 合并还是覆盖

- 合并：保留本机已有内容；同 ID 数据以备份中的版本为准。适合日常换设备。
- 覆盖：用备份替换应用数据，但保留当前设备上的 GitHub/WebDAV连接凭据。只适合新设备或明确需要回退时使用。
- 所有恢复操作都会先生成本机恢复点；如果任一存储写入失败，应用会尝试整体回滚。
