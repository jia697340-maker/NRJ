# 长期记忆与自动总结使用教程

本文面向第一次使用长期记忆功能的用户。你不需要了解 Token、向量或提示词，只要选择“想怎样整理”和“是否自动整理”即可。

先记住两件事：

1. 所有总结方式都不要求配置向量模型。
2. 不理解的高级设置保持默认值，不会影响正常使用。

## 一、最快开始方式

1. 打开某个联系人的聊天设置。
2. 进入“总结”。
3. 将“总结方式”设置为“综合记忆（推荐）”。
4. 开启“自动整理记忆”。
5. 保持默认的“系统自动判断”即可。

不配置独立总结节点时，系统会自动使用全局聊天节点。没有配置向量节点也不会影响自动总结、事件、变量或表格记忆。

## 二、怎样选择总结方式

总结方式只决定“保存什么内容”，不决定什么时候总结，也不决定是否使用向量模型。

### 综合记忆（推荐）

同时生成文字总结、角色感受、事件、人物资料、表格和关系记录。适合不知道该选什么，或者希望尽量完整保留经历的用户。

“综合”指总结内容的种类较多，不代表包含向量模型。没有向量模型也能完整生成这些记忆。

### 经典文字总结

把一段聊天整理成连贯的客观文字，最接近旧版总结。适合只想知道“之前发生过什么”的用户。

### 角色主观记忆

用角色第一人称保存感受、想法以及角色对关系的理解。系统会尽量把主观感受和客观事实分开。适合重视代入感和感情发展的用户。

### 重要事件记忆

重点记录事件中的人物、时间、地点、结果、决定和未完成事项。适合长篇剧情、连续任务和角色扮演。

### 人物资料与状态

重点维护称呼、喜好、禁忌、习惯、边界、关系、计划和当前状态。新信息会更新旧值，旧值仍保留在历史中。

### 分类表格记忆

把人物、地点、礼物、承诺、冲突等内容保存成可以逐项查看和修改的分类记录。适合喜欢自己管理资料的用户。

### 可以中途更换吗

可以。更换后只会影响以后新整理的内容，不会删除已经保存的记忆。

## 三、自动触发设置

### 系统自动判断（推荐）

消息条数或内容长度任意一项达到设置值，就会开始整理。普通用户选择这一项最省心。

### 按聊天条数

未总结消息达到设置数量后执行。默认 500 条。

数字越小，整理越频繁，请求总结接口的次数也可能越多。一般保持 300–500。

### 按内容长度

系统根据聊天文本长度估算 Token，超过阈值后执行。Token 只是内容长度单位，用户不需要自己计算。长消息较多时，这种判断比只看消息条数更及时。

### 重要标记触发

出现被标记的重要消息时提前整理，防止其在长对话中被遗漏。

是否必须：不是。经常使用重要标记时建议开启。

### 话题切换触发

系统通过本地关键词重合度判断最近对话是否明显转入新话题。该功能不会额外调用模型；容易频繁换话题的用户可以关闭。

是否必须：不是。聊天经常快速更换话题时建议关闭，避免过于频繁地整理。

### 空闲后台整理

设置若干分钟后，用户停止继续发送消息时整理当前积压内容。设置为 0 表示关闭。

是否必须：不是。普通用户保持 0 即可。

### 离开聊天时整理

离开当前聊天前处理尚未整理的内容。因为需要等待总结 API 返回，返回上一级页面可能比平时稍慢。

是否必须：不是。更在意及时保存记忆、可以接受返回变慢时再开启。

## 四、批次和记忆预算

- 一次最多整理多少条：一次发送给总结模型的最大消息数，建议保持 150。大量积压会自动拆成多批。调大可能使单次请求更慢，调小会增加请求次数。
- 每次最多读取多少旧记忆：每轮聊天允许读取的长期记忆长度，建议保持 1200 Token。调大能提供更多历史，但可能增加费用和噪声。
- 自动压缩很久以前的记忆：阶段摘要达到阈值后生成一条更精简的长期摘要。原摘要只会归档，不会被删除。建议开启并保持 8 条。

提高预算可以提供更多历史，但也会增加费用和噪声。系统不会再把整个记忆书架无条件注入每一轮对话。

## 五、独立总结节点

路径：应用的“API 节点配置” → “总结节点”。

1. 开启独立总结节点。
2. 选择服务商或填写自定义兼容地址。
3. 填写 API 密钥。
4. 同步或手动填写聊天补全模型。
5. 使用页面内的自定义测试弹窗检查连接。

总结节点未启用或配置不完整时，会继续使用全局聊天节点。

## 六、向量模型到底是什么

向量模型不负责生成总结，也不是任何总结方式的必需条件。它只负责在已经保存了很多记忆以后，帮助系统找到“意思相近”的旧记忆。

例如当前聊到“下个月出去玩”：

- 普通记忆搜索会查找相同关键词、重要记录和较新的记录。
- 向量搜索还可能找到措辞不同但意思相近的“下月旅行计划”。

没有配置向量时，页面会显示“正在使用普通记忆搜索”。这是正常状态，不是功能缺失。

向量节点完全可选，只用于提高大量长期记忆的语义召回效果。

路径：应用的“API 节点配置” → “向量节点”。

1. 开启独立向量节点。
2. 填写兼容 OpenAI `/v1/embeddings` 格式的 API 地址和密钥。
3. 填写真正的 Embedding 模型名称，不要填写普通聊天模型。
4. 点击“测试”，成功时会显示返回的向量维度。
5. 回到联系人的“总结”页面，点击“重新整理搜索索引”。

未配置向量节点时，系统自动使用关键词、人物、标签、时间、重要度和未完成状态混合召回。

更换 Embedding 模型后应重新构建索引。向量存储在 IndexedDB，不存入 localStorage；联系人正文、结构化记忆和备份仍可正常使用。

## 七、管理结构化记忆

在“总结”页面点击“结构化记忆”，可分别查看：

- 事件：事件摘要、重要度、时间、未完成事项和证据数量。
- 变量：分类、键、当前值、置信度、旧值数量和证据数量。
- 表格：人物、喜好、事件、承诺、礼物、关系、时间线、冲突和地点等分类。
- 关系：人物或实体之间带时间、置信度和证据的关系图谱。

每一项都可以编辑或删除。变量上的“锁定”用于保护人工确认的内容；锁定后，自动整理不会覆盖该变量的值。

删除或修改记忆时，已配置的向量索引会自动同步。也可以随时手动重建。

## 八、事实更新与证据

每个事件、变量和表格行都会保存来源消息 ID。变量发生变化时：

1. 新值成为当前有效值。
2. 旧值进入历史记录。
3. 后续聊天默认只注入当前有效值。
4. 人工锁定的值不会被自动覆盖。

模型输出仍有可能出错，因此建议定期检查关系状态、日期、承诺和敏感边界等重要记忆。

## 九、旧版数据兼容

旧版记忆书架会继续显示。首次使用新版记忆时，旧的总结游标会迁移为覆盖区间；以后手动总结任意区间，不会再导致前面的未总结内容被误跳过。

旧摘要可以直接参与本地召回；配置向量节点后，通过“重建”即可为旧摘要补充向量。

## 十、推荐配置

一般聊天：

- 综合记忆
- 系统自动判断
- 300–500 条
- 4000–6000 Token
- 单批 150 条
- 每次最多读取 1200 Token 旧记忆
- 重要标记触发开启
- 话题切换触发按需要开启

长篇角色扮演：

- 综合记忆或重要事件记忆
- 150–300 条
- 3000–5000 Token
- 每次最多读取 1200–1800 Token 旧记忆
- 建议配置独立总结节点和向量节点
